# iOS runtime core compilation

This harness compiles the real `rexcore` sources from OZORDI/LibertyRecomp commit `1922957d9f5a09acf0af12b918c43a910b3a13a5` for arm64 iOS. It avoids configuring unrelated desktop applications and game asset bundling. Dependencies are fetched at the commits recorded in that upstream tree.

The patch fixes a platform-header include-order bug in `memory_mac.cpp` and selects `vm_region_64` on iOS, where the SDK explicitly rejects `mach_vm.h`.

This is a compile-only milestone. It does not link or launch a complete game application and does not validate runtime memory mappings, exception handlers, fibres or threading behavior. In particular, compiler warnings about Darwin unnamed POSIX semaphores need runtime investigation before treating the threading implementation as usable.

The workflow preserves the upstream `librexcore.a` archive generated by Xcode. This archive is not an IPA, cannot be installed with Signulous, and is not a standalone SDK distribution with every dependency.

Remaining stages include linking a runtime smoke-test app, exercising guest memory and fibre switching on hardware, building the Vulkan/MoltenVK graphics backend for iOS, integrating game-data import, and compiling/linking the title application. The successful Swift diagnostic only establishes basic installation, Metal display, audio and Documents access.
